Blinking LED

The "hello world" of hardware. One LED on pin 13 turns on for one second, off for one second, forever. It proves the whole chain works: IDE → USB → chip → pin → light.

Book reference
Example 4-1
Parts
Uno + 1 LED
Pins used
D13, GND
Cycle
2 s (0.5 Hz)
Duty cycle
50 %
Build time
~5 min

The code

const int LED = 13;          // name pin 13 "LED"

void setup() {
  pinMode(LED, OUTPUT);      // pin 13 drives, not reads
}

void loop() {
  digitalWrite(LED, HIGH);   // 5 V on pin → LED on
  delay(1000);               // hold 1000 ms
  digitalWrite(LED, LOW);    // 0 V on pin → LED off
  delay(1000);               // hold 1000 ms
}

Line by line

const int LED = 13A named constant. Change one number to move the LED to another pin. setup()Runs once after power-up or reset. pinMode(…, OUTPUT)Configures the pin to push current out. Default is input. loop()Repeats forever — this is the whole program. digitalWrite HIGHPin goes to 5 V; current flows 13 → LED → GND. delay(1000)Chip waits 1,000 ms doing nothing else (blocking). digitalWrite LOWPin goes to 0 V; no voltage difference, LED off.

What the pin actually does

A digital pin has only two states. Blinking is just switching between them on a timer — a square wave with a 2-second period.

Run it

  1. Plug the Uno into the Mac via USB — green ON lights.
  2. IDE: Tools → Board → Arduino Uno, Tools → Port → /dev/cu.usbmodem…
  3. Type the sketch (or File → Examples → 01.Basics → Blink).
  4. Verify ✓ → "Done compiling" = code turned into machine instructions.
  5. Upload → board resets, TX/RX flicker, sketch stored in flash.
  6. LED blinks. Unplug and replug — it still blinks; the sketch stays until overwritten.

Experiments — change one thing at a time

Faster blink

Set both delays to 200. At ~20 ms each (25 Hz) your eye stops seeing the blink — the LED just looks dimmer. That's the idea behind PWM.

Heartbeat

Uneven timing: on 100, off 100, on 100, off 700. Same code, different rhythm.

int t[] = {100,100,100,700};
for (int i=0;i<4;i++){
  digitalWrite(LED, i%2==0);
  delay(t[i]);
}

SOS in Morse

3 short (200 ms), 3 long (600 ms), 3 short, pause 2 s. First "real" message from a machine.

Limits — know what you're skipping

  • No resistor here: a blue LED can pull ~30–40 mA, above the 20 mA pin rating. Fine for a demo, not for hours.
  • Proper build: LED + 220 Ω resistor on a breadboard → ~10 mA (C-02)
  • delay() freezes the chip — it can't read a button meanwhile. Later fix: millis()
  • Only pin 13 sits next to GND on the header — other pins need a breadboard

Quick self-check

What happens if you delete pinMode()?

Pin stays an input; LED glows very faintly or not at all (only the weak internal pull-up drives it).

How many times does it blink per minute?

30 — one full cycle every 2 seconds.

Make it blink on pin 8 — what changes?

One number: const int LED = 8; — and move the LED (with a resistor, via breadboard).

Why does the L LED blink too?

It's wired to pin 13 on the board. Same pin, same signal.

For the kids: we tell the tiny brain "light on, count to one, light off, count to one" — and it never gets bored.
